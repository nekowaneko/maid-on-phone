## 重點

**`OverlayService.kt`**
- 新增 `refreshDrinkEnabled()`：`WorkerApi.get(ENABLED_PATH)`，回呼裡先確認服務仍是 `RUNNING`；只有 HTTP 2xx 且 JSON 的 `enabled` 欄位是布林值時才取值，否則傳 `null`；結果交給 `drinkUiEnabled(status, enabled)`，再 `callJs("window.pet.setDrinkEnabled&&window.pet.setDrinkEnabled($flag)")`。
- `$flag` 只能是 `true` 或 `false` 兩個字面值，**不得拼接任何來自伺服器的文字**（A68）。
- 呼叫時機：頁面載入完成（`pageReady` 變 true 之後）與每次泡泡由收起變展開時。角色未顯示時不讀。
- **不得**把結果存到任何本機儲存（不加 `SharedPreferences`、檔案或靜態變數快取，A66）。
- 不得在這裡寫 `catch` 後預設為開的備援；讀不到的降級已經由 `drinkUiEnabled` 一處負責（A67）。
- 不新增 `@JavascriptInterface`（V08 仍恰好 6 個）。

**`DrinkSettingsActivity.kt`**
- 在「訂閱名稱」之前加開關列，標題「啟用戒飲記錄」，元件用 `androidx.appcompat.widget.SwitchCompat`，預設顯示為開；不加說明文字、不改其他欄位的樣式與順序。
- `loadSettings()`：設定讀取成功並填完欄位後，接著 `GET ENABLED_PATH`；成功且 `enabled` 為布林值才填開關並啟用儲存鈕。失敗或格式不對時顯示固定提示、儲存鈕維持停用。**這裡不套用 `drinkUiEnabled`**（設定畫面讀不到就不讓存，不是降級情境）。
- `saveSettings()`：先 `PUT` 設定（五個欄位，內容與現在完全相同，**body 不得含 `enabled`**），成功後才 `PUT ENABLED_PATH`（`{"enabled":true|false}`）。設定那步失敗就不送開關；開關那步失敗顯示該步錯誤，不回滾已存的五個欄位；兩步都成功才顯示「已儲存」。
- 開關為關時，其他欄位仍可編輯與儲存。
