## 4. 模組介面規格（固定，規格測試依賴）

### 4.1 Kotlin：套件 `com.accompany.pet.core.chat`

```kotlin
const val CHAT_NOT_SET_MESSAGE = "還沒設定聊天網址，見 docs/WORKER-SETUP.md"
fun normalizeChatUrl(raw: String?): String?
// trim 後必須以 https:// 開頭（不分大小寫）且主機名稱非空，否則 null；其餘原樣回傳（不改路徑）
fun isSameOrigin(baseUrl: String, targetUrl: String): Boolean
// 比較 scheme、主機（不分大小寫）、埠號（沒寫時 https 為 443）；任一方無法解析回傳 false
// 不得使用 java.net（V02）：以字串自行解析「scheme://主機[:埠號][/其餘]」
enum class ChatAction { OPEN, SHOW_NOT_SET }
fun decideChat(rawUrl: String?): ChatAction   // normalizeChatUrl 為 null → SHOW_NOT_SET，否則 OPEN
```

### 4.2 JavaScript：`backend/core/push.js`（純函式，不讀檔、不連線）

```js
export const MAX_PUSH_TEXT_LENGTH = 500
export const PUSH_NOT_CONFIGURED_MESSAGE = '尚未設定推播'
export const PUSH_FORMAT_MESSAGE = '請求格式不正確：缺少 text 欄位。'
export const PUSH_TOO_LONG_MESSAGE = '訊息太長了。'
export const PUSH_FAILED_MESSAGE = '推播送出失敗'
// 檢查請求內容：text 須為字串且 trim 後非空，否則 { ok: false, reason: 'format' }；
// 超過 500 字 { ok: false, reason: 'too_long' }；id 有給（非空字串）就原樣保留，否則為 null
export const validatePushPayload = (payload) => ({ ok: true, text, id })
// 產生新編號：`push-${nowMs.toString(36)}-${randomText}`
export const newPushId = (nowMs, randomText) => '...'
// 組出 FCM HTTP v1 的訊息：只有 token、data（id、text）、android.priority = 'high'，沒有 notification
export const buildFcmMessage = (deviceToken, id, text) => ({ message: { token, data: { id, text }, android: { priority: 'high' } } })
// 服務帳戶 JSON 可解析且含 project_id、client_email、private_key，推播代碼為非空字串，才算已設定
export const isPushConfigured = (serviceAccountText, deviceToken) => true
```

### 4.3 JavaScript：推播客戶端（`backend/worker/fcm-client.js` 與 `.stub.js` 同介面）

```js
// 送出一則訊息；回傳 { ok: true, name } 或 { ok: false, status, code }
// code：Google 錯誤回應中 error.details[].errorCode，沒有時用 error.status，再沒有時用 'UNKNOWN'
export const sendFcm = async (message, serviceAccountText, fetchImpl = fetch) => ({ ok: true, name })
```
真實版流程：解析服務帳戶 → 以 WebCrypto 匯入 PKCS#8 私鑰（去掉 PEM 標頭、標尾與換行後 base64 解碼）→ 簽 RS256 JWT（`iss`／`sub` = client_email、`aud` = `https://oauth2.googleapis.com/token`、`scope` = `https://www.googleapis.com/auth/firebase.messaging`、`iat`、`exp` = iat + 3600）→ POST `https://oauth2.googleapis.com/token` 換存取權杖 → POST `https://fcm.googleapis.com/v1/projects/{project_id}/messages:send`。權杖不快取。
Stub 版：把收到的訊息存進陣列供測試讀取；可設定成回傳失敗 `{ ok: false, status: 404, code: 'UNREGISTERED' }`。

### 4.4 推播路由：`POST /api/push`（`handlers.js`）

`createHandler(deps)` 的 deps 新增：`pusher(message)`（已綁好服務帳戶的 `sendFcm`）、`pushConfig: { serviceAccount, deviceToken }`、`randomText()`（產生編號用，測試可注入）。`now` 沿用既有的 `deps.now`。

處理順序（固定）：存取密鑰（沿用既有 `/api/` 授權，401 `{ error: '未授權。' }`）→ `validatePushPayload` → `isPushConfigured` → `buildFcmMessage` → `pusher` 呼叫一次。

| 情況 | HTTP | 回應主體 |
|---|---|---|
| 密鑰錯誤或沒帶 | 401 | `{ "error": "未授權。" }` |
| text 空白或缺少 | 400 | `{ "error": "請求格式不正確：缺少 text 欄位。" }` |
| text 超過 500 字 | 400 | `{ "error": "訊息太長了。" }` |
| 尚未設定服務帳戶或推播代碼 | 503 | `{ "error": "尚未設定推播" }` |
| 送出成功 | 200 | `{ "ok": true, "id": "<編號>" }` |
| Google 回錯誤 | 502 | `{ "ok": false, "error": "推播送出失敗", "code": "<錯誤代碼>" }` |

非 POST 方法回 405（沿用既有的 `METHOD_NOT_ALLOWED_MESSAGE`）。

### 4.5 App 介面

- `worker.properties` 的 `chatUrl` → `BuildConfig.CHAT_URL`（不存在時為空字串），寫法同 M1 的 `firebase.properties`
- `index.html`：泡泡中「說話」與「聊聊」放在同一列，**「聊聊」在「說話」右邊**；按鈕 `<button id="chat" type="button">💬 聊聊</button>`，點擊呼叫 `callBridge('onChatPressed')`
- `OverlayService.onChatPressed`：重設閒置計時 → `decideChat(BuildConfig.CHAT_URL)` → `SHOW_NOT_SET` 時 `showText(CHAT_NOT_SET_MESSAGE)`；`OPEN` 時收起泡泡、以 `FLAG_ACTIVITY_NEW_TASK` 開啟 `ChatActivity`
- `ChatActivity`：全螢幕 WebView，JavaScript 與 DOM storage 開啟（聊天網頁用它記存取密鑰與聊天紀錄）；`shouldOverrideUrlLoading` 對非同源網址回傳 true（擋下、停在原頁）；`shouldInterceptRequest` 對非同源子資源回 403；返回鍵在可返回時 `goBack()`，否則結束畫面；網址為 null 時直接結束（防禦）
- `MainActivity`：新增一行「聊天網址：已設定」或 `CHAT_NOT_SET_MESSAGE`
