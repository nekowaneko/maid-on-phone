## 4. 模組介面規格（固定，規格測試與另外兩條線都依賴它）

### 4.1 推播資料（D 送出、C 解析）

FCM `data`：`{ id, text }` 或 `{ id, text, script }`，三者都是字串。
- `text`：去掉所有合法標籤後 trim 的純文字（通知欄顯示用）
- `script`：使用者送來的原文 trim 後（含標籤，角色演出用）；只在原文含合法標籤時出現（A27）

### 4.2 Worker（D）

`POST /api/push` 主體不變：`{ text, id? }`，`text` 可以含標籤。處理順序（固定）：授權 → `validatePushPayload`（沿用：空白 400、超過 500 字 400，長度以原文計）→ **剝標籤**（`handlers.js` 以 `feedAll([text], deps.emotionConfig.emotionMap, deps.emotionConfig.defaultEmotion)` 再 `finalize`，取 `.text.trim()`）→ 剝完為空字串時回 400 `PUSH_FORMAT_MESSAGE`、不送出 → `isPushConfigured` → `buildFcmMessage` → `pusher` 一次。

```js
// push.js：第 4 個參數可省略；script 為非空字串時 data 才加 script 欄位
export const buildFcmMessage = (deviceToken, id, text, script) => ({ message: { token, data: { id, text, script? }, android: { priority: 'high' } } })
```
「含合法標籤」的判定：剝完的純文字（trim 前）與原文不同，即視為含標籤。
`tools/send_push.py` 加選用參數 `--script`，有給時 data 多帶 `script`（直接送 FCM 的測試工具，不經 Worker，不自動剝標籤）。

### 4.3 角色頁（B）

一般 script，依序載入：`emotion-map.js` → `vendor/stream-parser.js` → `performance.js` → `index.html` 內嵌程式。

`vendor/stream-parser.js` 掛 `PetStreamParser = { createParserState, feedChunk, finalize, cuesReadyAt, feedAll }`（`extractSseEvents` 可一併掛上）。

`performance.js` 掛 `PetPerformance`（全部是純函式，不碰 DOM、不讀時間）：
```js
TIMING = { leadMs: 450, charMs: 30, holdMs: 3000 }   // 照抄 accompany_bot 的 LEAD_MS、TYPEWRITER_INTERVAL_MS、HOLD_MS
planTimeline(script, frames, defaultEmotion) → { text, steps, endMs }
  // 以 feedAll([script]) + finalize 解析；steps 依 atMs 遞增排列，每一步是 { atMs, face } 或 { atMs, count }
  // atMs 0：{ face: 第一個字的表情（index 0 的 cue，沒有則 defaultEmotion）}
  // 第 k 個字（1 起算）：{ atMs: leadMs + (k-1)*charMs, count: k }
  // index i（i>0）的 cue：{ atMs: 第 i+1 個字的時間, face }，排在同一時間的 count 步驟之前
  // index ≥ 字數的 cue（標籤在最後）：排在最後一個字的時間，count 步驟之後
  // 結尾：{ atMs: endMs, face: defaultEmotion }，endMs = 最後一個字的時間 + holdMs（沒有字時以 leadMs 當最後一個字的時間）
frameFor(emotion, emotionMapConfig) → 檔名   // frames 有這個鍵就回它的檔名，否則回 frames[defaultEmotion]
createStage() → { current: null, waiting: [] }
stageSay(stage, script) → stage              // current 為 null 就設為 current；否則加到 waiting 尾端
stageFinish(stage) → stage                   // current 換成 waiting 第一個；沒有就 null
stageSkip(stage, frames, defaultEmotion) → { stage: createStage(), text, face: defaultEmotion }
                                             // text：current 與 waiting 依序各自解析後的純文字，以空一行（\n\n）串接
```
所有函式不得改動傳入的物件（不可變更新）。

`index.html` 內嵌程式（原生 → 網頁的介面 `window.pet`）：
- `say(script)`：`stageSay`；若原本沒在演，立刻開演 current。開演＝依 `planTimeline` 排計時器：face 步驟換整張表情圖（`frameRoot + frameFor(...)`），count 步驟以 `textContent` 顯示前 count 個字並捲到泡泡底部。到 `endMs` 時 `stageFinish`，有下一則就接著演。
- `showText(text)`（沿用）：先執行跳到演完（同 `skip`），再以 `textContent` 顯示 text，臉為平常的臉。
- `showBubble(false)` 與 `setRender('paused')`：若正在演出，執行跳到演完——清掉所有演出計時器，泡泡顯示 `stageSkip` 的 text，臉換回平常的臉。
- 換臉沿用 accompany_bot face-swap 的原則：新圖載入失敗時保留上一張臉（不出現空白）。
- 眨眼：只有畫面上是 `idleFrame` 時才排眨眼；換成其他表情時取消眨眼，換回 idle 時恢復。
- 不新增 `PetBridge` 方法（`@JavascriptInterface` 維持 3 個）。
