## 2. 架構

```
[Android App（Kotlin 原生殼）]
 ├─ OverlayService（前景服務，type=specialUse）
 │   └─ 透明 WebView → 載入本機角色頁（預錄待機循環）；泡泡「聊聊」開啟 ChatActivity（WebView 只載入 Worker B 網址）
 ├─ PetTileService（快速設定磚 🐾）
 ├─ ForegroundDetector（使用情形存取權；只在收到推播當下讀一次前景 App）
 ├─ SpeechBridge（原生 SpeechRecognizer → 文字傳給 WebView）
 └─ PetMessagingService（收推播 → 角色出現／一般通知／排隊）

[PWA 主程式（Chrome，維持現狀）]

[Cloudflare]（Worker B：accompany_bot Worker 的獨立副本，見 2.2）
 ├─ Workers：/chat（陪伴聊天）、/pet API、LLM 呼叫、意圖解析
 ├─ Cron：盤前計算、P3 掃描、飲料時段詢問
 ├─ D1：唯一資料來源（共享資料一律放這裡）
 └─ FCM 發送
```

### 2.1 已定案的技術決策

| 項目 | 決策 | 理由 |
|---|---|---|
| 懸浮介面 | 懸浮窗＋透明 WebView | 唯一能「看得到、會動、可點」的方式，且能沿用現有渲染器 |
| 懸浮窗大小 | 只開到角色外框大小 | 避開 Android 12 的觸控穿透透明度限制 |
| 出現方式 | **需要時才出現**：點磁磚、角色模式開時收到提醒、點通知才出現；閒置 3 分鐘自動收起，不常駐 | M0 實測：vivo 關螢幕約 5 秒凍結、約 3.5 分鐘收掉 App，白名單無效；常駐等於和系統對抗 |
| 待機呈現 | 待機播預錄差分循環（呼吸 JS 每秒 10 格、眨眼）；互動表情沿用 accompany_bot 的分層 PNG（v1.4 定案，不導入 Inochi2D） | 降低耗電；M0 實測 App 自身 CPU 約佔 8 小時電量 1% |
| 資料 | D1 為準，懸浮窗用 token 讀寫 | Chrome PWA 與 App 內 WebView 的 localStorage 不互通 |
| 語音輸入 | 原生 SpeechRecognizer | Android WebView 通常不支援 Web Speech API |
| 台股資料 | 證交所 OpenAPI 日資料 | 只需盤後資料，免費、官方 |
| LLM 使用 | 只用在「自然語言 → 結構化指令」與台詞生成；均線、熱量、到期判斷一律用規則 | 避免亂猜、壓低成本 |
| 發布 | 自用 APK，限量發布開發者帳號 | 2026/8 起未驗證開發者安裝需額外流程 |
| 開源 | 程式碼 MIT；API 金鑰、角色立繪不進公開 repo | |
| 後端來源 | 方案 A：複製 accompany_bot 的 Worker 成獨立副本 | 兩個產品完全獨立，開源乾淨，資料與金鑰不共用 |

## 3. 角色行為規則

### 3.1 狀態機

角色不常駐（v1.3）。「角色模式」由快速設定磚切換，決定提醒來時由角色說還是發通知。

| 狀態 | 畫面 | 進入條件 | 提醒怎麼送 |
|---|---|---|---|
| 收起 | 無（平常狀態） | 閒置 3 分鐘、使用者收起、或被系統收掉 | 依下列判斷 |
| 出現 | 懸浮角色（待機循環＋泡泡） | 點磁磚開啟、角色模式開時收到提醒、點通知 | 角色說＋泡泡 |

收到提醒時的判斷（依序）：

| 條件 | 結果 |
|---|---|
| 同一編號已處理過 | 忽略 |
| 正在玩遊戲 | 排隊；通知欄放一則靜音的「有 N 則提醒等你」，不出聲、不彈出 |
| 角色模式開 | 角色出現並說出提醒 |
| 角色模式關 | 一般推播（頭像＋文字；按鈕於 M2 起依功能加入） |

### 3.2 遊戲判斷

- **只在收到提醒的當下**讀一次前景 App，不常駐監看（v1.3 起取消每 2～3 秒輪詢）。
- 判定為遊戲：App 宣告 `CATEGORY_GAME`，或在使用者自訂的遊戲清單內。
- 沒有「使用情形存取權」時視為沒在玩遊戲，主畫面提示開啟。
- 排隊的提醒在**下一次角色出現時**報告（點磁磚、點靜音通知、或沒在玩遊戲時收到下一則）；不主動偵測離開遊戲。
- 排隊上限：**滿 2 小時的提醒過期丟掉**，只報告仍有效的；最多保留 20 則。

### 3.3 喚起與關閉

- 手動：快速設定磚 🐾 切換角色模式；開啟時角色立刻出現，關閉時角色收起。
- 自動：伺服器有提醒時以 FCM 推播送達，依 3.1 的判斷處理。
- 自動收起：出現後 3 分鐘沒有任何互動（點角色、點泡泡、拖曳、按麥克風）就收起。
- 常駐通知：角色出現期間依系統規定存在，設為最低重要性、靜音；角色收起即移除。

### 3.4 複述確認（寫入前一律先確認）

| 動作 | 確認方式 |
|---|---|
| 新增飲料紀錄 | 複述品項／大小／甜度／冰量／熱量 → 「對，記下來／改甜度／取消」 |
| 記錄「今天沒喝」 | 一鍵，不需確認（可撤銷） |
| Todoist 改到期日或優先級 | 泡泡三選一本身即確認 |
| 任何刪除 | 第一版不提供 |

### 3.5 表情標籤

沿用「先輸出標籤、再輸出台詞」。第一版需要的標籤：待機貌、微笑貌、害羞貌、擔心貌、驚訝貌、思考貌。實際可用的標籤以 accompany_bot 的 `emotion-map.json` 為準（v1.4：分層 PNG，換臉部圖層），待機仍播預錄差分。

2026-10-04：persona.md 改為「微傲／一句嬌」結構，需新增對應的表情差分（微傲、嬌各至少一張臉部圖層），素材畫好後加進 `emotion-map.json`。

## 4. 功能規格

### F0.5 陪伴核心

- **來源**：accompany_bot 現有的人設、劇本式表情（先輸出「xx貌」標籤再輸出台詞）、安全邊界、角色小檔案（進 system prompt 當長期記憶）。
- **入口**：點懸浮角色 → 泡泡「說話」右邊的「聊聊」→ 開啟聊天畫面（WebView 只載入 Worker B 網址），打字輸入。聊天畫面改以角色頭貼呈現表情的做法，待複製 accompany_bot 後再討論。
- **表情演出**：標籤驅動分層 PNG 表情（v1.4 定案）；待機時仍播預錄差分（見 M0 結論）。
- **台詞統一出口**：F1～F3 所有提醒與回覆都經過人設產生，不得出現制式文字。數字（熱量、金額、均線）由規則算好後交給人設「說出來」，LLM 不得改動數字。
- **安全邊界**：沿用 accompany_bot 現況：輸入或輸出被 Gemini 安全過濾擋下時，改說預設台詞。（v1.4 更正：accompany_bot 實際沒有「焦慮過頭時提醒就醫」的機制，之後若要做另行規劃。）

### F1 戒飲記錄

- **輸入**：點角色 → 語音或打字；推播／泡泡上的「沒喝」按鈕。
- **主動詢問**：每天 15:00（時間可設定）她問「今天有喝飲料嗎？」，附「沒喝／有喝，用說的」。
- **解析**：LLM 把口語轉成 `{品項, 大小, 甜度, 冰量}`；熱量查**熱量表**（D1 表格，常喝品項先手動建立），查不到時請使用者選最接近的品項，不讓 LLM 估。
- **寫入**：見 §6 待確認事項（戒飲存訂閱 API）。
- **回報**：本週杯數、本月省下金額、訂閱回本 %、少攝取熱量。
- **語氣**：喝了也不能用罪惡感語氣。

### F2 Todoist 雙軌提醒

使用者的優先級定義（以此為準）：

| 優先級 | 意義 | 例子 | 會出的問題 |
|---|---|---|---|
| P2 | 對未來重要、還沒到期，早做早準備 | 教師證加科登記、延長修業年限、準備一年後的課程 | 一直拖，最後變急事 |
| P3 | 時程已確定，但現在做不到 | 確認畢業時辰 | 寫了就忘，時機到了沒想起來 |

#### F2a：P2 催進度

- **掃描**：每天一次，找出 P2 且最後修改超過 N 天（預設 14）的任務。
- **頻率**：每週最多提一件，選擱置最久的那件。
- **台詞方向**：鼓勵先做最小的一步，不責備。
- **選項**：今天推進一小步（到期日設今天）／延後一週（下次掃描跳過 7 天）／拆成小步驟。
- **拆成小步驟**：由 LLM 提出 2～3 個子任務 → 複述確認 → 建立為 Todoist 子任務。

#### F2b：P3 時機到提醒

- **「可以開始做的日期」**：使用 Todoist 的到期日欄位。
- **時機到**：到期日當天早上提醒，選項：今天做／明天再提醒。
- **沒有日期的 P3**：每件只問一次「這件事什麼時候可以做？」，使用者回答日期 → 複述確認 → 寫入到期日；回答「不知道」則標記為已詢問，不再追問。
- **晚上追問**：當天選「今天做」且 21:00 前未完成，再提醒一次。

#### F2 共通

- 每天最多出聲 2 次（P2 一件＋P3 一件），避免噪音。
- 所有寫入 Todoist 的動作都先複述確認（泡泡選項本身即確認）。

### F3 盤前均線排列

- **時間**：交易日 08:30（遇休市不發）。
- **計算**：用前一交易日收盤資料算 5／20／60 日均線，排出上下順序並套用規則：
  - 5 > 20 > 60：多頭排列
  - 60 > 20 > 5：空頭排列
  - 其他：依交叉狀況給一句描述（例：5 日線跌破 20 日線，短線轉弱）
- **輸出**：開場一句經人設產生（帶表情標籤）；每檔一行與結尾的「僅供參考，非投資建議」一律由規則產生，不經 LLM（2026-10-04 定案，F0.5「台詞統一出口」的例外）。
- **追蹤清單**：設定檔讀取（使用者之後提供）。
