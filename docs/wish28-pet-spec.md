## 2. 架構

```
[Android App（Kotlin 原生殼）]
 ├─ OverlayService（前景服務，type=specialUse）
 │   └─ 透明 WebView → 載入 /pet 頁（Inochi2D 渲染器，沿用 accompany_bot）
 ├─ PetTileService（快速設定磚 🐾）
 ├─ GameWatcher（使用情形存取權，偵測前景 App）
 ├─ SpeechBridge（原生 SpeechRecognizer → 文字傳給 WebView）
 └─ FcmService（收推播：喚醒角色或改發一般通知）

[PWA 主程式（Chrome，維持現狀）]

[Cloudflare]（Worker B：accompany_bot Worker 的獨立副本，見 2.2）
 ├─ Workers：/chat（陪伴聊天）、/pet API、LLM 呼叫、意圖解析
 ├─ Cron：盤前計算、P3 掃描、飲料時段詢問
 ├─ D1：唯一資料來源（共享資料一律放這裡）
 └─ FCM 發送
```

### 2.1 已定案的技術決策

| 項目 | 決策 | 理由 |
|---|---|---|
| 懸浮介面 | 懸浮窗＋透明 WebView | 唯一能「看得到、會動、可點」的方式，且能沿用現有渲染器 |
| 懸浮窗大小 | 只開到角色外框大小 | 避開 Android 12 的觸控穿透透明度限制 |
| 待機呈現 | 待機播預錄差分循環（呼吸、眨眼），互動時才切換即時 Inochi2D | 降低耗電 |
| 資料 | D1 為準，懸浮窗用 token 讀寫 | Chrome PWA 與 App 內 WebView 的 localStorage 不互通 |
| 語音輸入 | 原生 SpeechRecognizer | Android WebView 通常不支援 Web Speech API |
| 台股資料 | 證交所 OpenAPI 日資料 | 只需盤後資料，免費、官方 |
| LLM 使用 | 只用在「自然語言 → 結構化指令」與台詞生成；均線、熱量、到期判斷一律用規則 | 避免亂猜、壓低成本 |
| 發布 | 自用 APK，限量發布開發者帳號 | 2026/8 起未驗證開發者安裝需額外流程 |
| 開源 | 程式碼 MIT；API 金鑰、角色立繪不進公開 repo | |
| 後端來源 | 方案 A：複製 accompany_bot 的 Worker 成獨立副本 | 兩個產品完全獨立，開源乾淨，資料與金鑰不共用 |

### 2.2 後端複製方式（方案 A）

| 步驟 | 做什麼 |
|---|---|
| 1 | 把 accompany_bot 的 Worker 資料夾複製到 `pet-maid/backend/` |
| 2 | `wrangler.toml` 改名為 `pet-maid-api`；新建 D1 資料庫 `pet-maid-db` |
| 3 | 重新設定 API 金鑰（建議另開一把，方便分開看用量） |
| 4 | 部署後的新網址寫進 App 設定，懸浮窗 WebView 連這個網址 |
| 5 | Inochi2D 渲染器與表情素材複製到 App 的 `assets/` |

| 複製過去 | 不共用 |
|---|---|
| 人設、劇本式表情解析、安全邊界、角色小檔案程式、聊天 API | 聊天紀錄、D1 資料庫、API 金鑰 |

**人設同步規則**：人設獨立成 `persona.md`。accompany_bot 改人設後，只要把這一個檔案複製過來並重新部署，不重新同步整份程式。

## 3. 角色行為規則

### 3.1 狀態機

| 狀態 | 畫面 | 進入條件 | 提醒怎麼送 |
|---|---|---|---|
| 顯示 | 懸浮角色（待機循環） | 磁磚開啟、非遊戲中 | 角色出聲＋泡泡選項 |
| 遊戲中 | 完全隱藏 | 前景 App 是遊戲 | 排隊 |
| 關閉 | 無 | 磁磚關閉 | 一般推播（頭像＋最多 2 顆按鈕） |

### 3.2 遊戲偵測

- 每 2～3 秒讀一次前景 App（僅螢幕開啟時）。
- 判定為遊戲：App 宣告 `CATEGORY_GAME`，或在使用者自訂的遊戲清單內。
- 離開遊戲：角色自動回來，一句話總結排隊的事。
- 排隊上限：**超過 2 小時的提醒過期丟掉**，只報告仍有效的。

### 3.3 喚起與關閉

- 手動：快速設定磚 🐾 切換顯示／關閉。
- 自動：伺服器有提醒時，以 FCM 高優先推播喚醒（磁磚開啟時角色出現；關閉時改發一般推播）。
- 常駐通知：系統規定必須存在，設為最低重要性、靜音。

### 3.4 複述確認（寫入前一律先確認）

| 動作 | 確認方式 |
|---|---|
| 新增飲料紀錄 | 複述品項／大小／甜度／冰量／熱量 → 「對，記下來／改甜度／取消」 |
| 記錄「今天沒喝」 | 一鍵，不需確認（可撤銷） |
| Todoist 改到期日或優先級 | 泡泡三選一本身即確認 |
| 任何刪除 | 第一版不提供 |

### 3.5 表情標籤

沿用「先輸出標籤、再輸出台詞」。第一版需要的標籤：待機貌、微笑貌、害羞貌、擔心貌、驚訝貌、思考貌。每個標籤要有預錄差分（待機用）與 Inochi2D 表情（互動用）兩份。

## 4. 功能規格

### F0.5 陪伴核心

- **來源**：accompany_bot 現有的人設、劇本式表情（先輸出「xx貌」標籤再輸出台詞）、安全邊界、角色小檔案（進 system prompt 當長期記憶）。
- **入口**：點懸浮角色 → 泡泡選「聊聊」→ 展開 WebView 面板，打字或語音。
- **表情演出**：標籤驅動 Inochi2D 表情；待機時仍播預錄差分（見 M0 結論）。
- **台詞統一出口**：F1～F3 所有提醒與回覆都經過人設產生，不得出現制式文字。數字（熱量、金額、均線）由規則算好後交給人設「說出來」，LLM 不得改動數字。
- **安全邊界**：沿用 accompany_bot 的做法；使用者焦慮過頭時提醒就醫的機制一併保留。

### F1 戒飲記錄

- **輸入**：點角色 → 語音或打字；推播／泡泡上的「沒喝」按鈕。
- **主動詢問**：每天 15:00（時間可設定）她問「今天有喝飲料嗎？」，附「沒喝／有喝，用說的」。
- **解析**：LLM 把口語轉成 `{品項, 大小, 甜度, 冰量}`；熱量查**熱量表**（D1 表格，常喝品項先手動建立），查不到時請使用者選最接近的品項，不讓 LLM 估。
- **寫入**：見 §6 待確認事項（戒飲存訂閱 API）。
- **回報**：本週杯數、本月省下金額、訂閱回本 %、少攝取熱量。
- **語氣**：喝了也不能用罪惡感語氣。

### F2 Todoist 雙軌提醒

使用者的優先級定義（以此為準）：

| 優先級 | 意義 | 例子 | 會出的問題 |
|---|---|---|---|
| P2 | 對未來重要、還沒到期，早做早準備 | 教師證加科登記、延長修業年限、準備一年後的課程 | 一直拖，最後變急事 |
| P3 | 時程已確定，但現在做不到 | 確認畢業時辰 | 寫了就忘，時機到了沒想起來 |

#### F2a：P2 催進度

- **掃描**：每天一次，找出 P2 且最後修改超過 N 天（預設 14）的任務。
- **頻率**：每週最多提一件，選擱置最久的那件。
- **台詞方向**：鼓勵先做最小的一步，不責備。
- **選項**：今天推進一小步（到期日設今天）／延後一週（下次掃描跳過 7 天）／拆成小步驟。
- **拆成小步驟**：由 LLM 提出 2～3 個子任務 → 複述確認 → 建立為 Todoist 子任務。

#### F2b：P3 時機到提醒

- **「可以開始做的日期」**：使用 Todoist 的到期日欄位。
- **時機到**：到期日當天早上提醒，選項：今天做／明天再提醒。
- **沒有日期的 P3**：每件只問一次「這件事什麼時候可以做？」，使用者回答日期 → 複述確認 → 寫入到期日；回答「不知道」則標記為已詢問，不再追問。
- **晚上追問**：當天選「今天做」且 21:00 前未完成，再提醒一次。

#### F2 共通

- 每天最多出聲 2 次（P2 一件＋P3 一件），避免噪音。
- 所有寫入 Todoist 的動作都先複述確認（泡泡選項本身即確認）。

### F3 盤前均線排列

- **時間**：交易日 08:30（遇休市不發）。
- **計算**：用前一交易日收盤資料算 5／20／60 日均線，排出上下順序並套用規則：
  - 5 > 20 > 60：多頭排列
  - 60 > 20 > 5：空頭排列
  - 其他：依交叉狀況給一句描述（例：5 日線跌破 20 日線，短線轉弱）
- **輸出**：每檔一行；結尾固定附「僅供參考，非投資建議」。
- **追蹤清單**：設定檔讀取（使用者之後提供）。

## 5. 里程碑與驗收（每項可打勾）

### M0：耗電實測（先做，結果決定後續）

- [ ] 最小 APK：懸浮窗＋透明 WebView，只播待機循環，不接 AI
- [ ] 透明背景在使用者手機上正常（不是黑底）
- [ ] 螢幕開啟、角色常駐 8 小時，記錄耗電增加量（目標值待實測後決定，暫定 ≤ 5%）
- [ ] 鎖螢幕後渲染停止
- [ ] 手機省電機制沒有把服務殺掉（若有，記錄需要的系統設定）
- [ ] 原生 SpeechRecognizer 能把中文語音轉成文字並傳進 WebView

**M0 不通過時**：待機改成純原生圖片循環（不開 WebView），點擊時才建立 WebView。

### M1：基礎建設（F0）

- [ ] 快速設定磚可開關角色
- [ ] 角色可拖曳、放開後吸附邊緣、位置會被記住
- [ ] 進入遊戲時角色隱藏；離開後出現並總結排隊提醒
- [ ] 超過 2 小時的排隊提醒不會被報告
- [ ] 磁磚關閉時，伺服器提醒改以一般推播送達
- [ ] Cloudflare 送 FCM 能在背景喚醒角色
- [ ] 表情標籤能切換待機差分與 Inochi2D 表情

### M1.5：陪伴核心接入（F0.5）

- [ ] Worker B 依 §2.2 部署完成，與 accompany_bot 使用不同的 D1 與金鑰
- [ ] **Inochi2D 在懸浮窗 WebView 裡能正常渲染**（透明背景、不閃退）；不行時記錄原因，互動改用差分圖片
- [ ] 互動時從預錄待機切換到 Inochi2D，結束後切回，切換過程不閃黑
- [ ] 回覆的「xx貌」標籤正確觸發對應表情
- [ ] 人設來自獨立的 `persona.md`
- [ ] 安全邊界與 accompany_bot 行為一致（用同一組測試句對照）
- [ ] 角色小檔案可編輯，修改後下一輪對話生效
- [ ] 規則算出的數字經人設說出時不被改動（用 3 組數字對照）

### M2：戒飲記錄（F1）

- [ ] 說「剛喝大杯珍奶半糖去冰」→ 正確複述四個欄位與熱量
- [ ] 「改甜度」能修改後重新複述
- [ ] 確認後資料寫入，回報數字與資料庫一致
- [ ] 15:00 主動詢問；「沒喝」一鍵記錄
- [ ] 熱量表查不到的品項，不會出現 LLM 自己估的數字

### M3：Todoist 雙軌提醒（F2）

- [ ] P2：最後修改超過 14 天的任務會被提出，每週最多一件
- [ ] P2：「延後一週」後，7 天內不再提同一件
- [ ] P2：「拆成小步驟」確認後，子任務正確建立在原任務底下
- [ ] P3：到期日當天早上提醒；到期日之前不出聲
- [ ] P3：沒有日期的任務只被問一次；回答日期後正確寫入到期日
- [ ] P3：「今天做」未完成時 21:00 再提醒一次
- [ ] 每天出聲不超過 2 次

### M4：盤前均線（F3）

- [ ] 交易日 08:30 送出；休市日不送
- [ ] 至少用 3 檔標的、手算對照均線排列結果一致
- [ ] 每則都附免責聲明
