## 步驟（四件事都要真的比對，不得只靠單元測試）

1. **後端 ↔ Kotlin 的契約**：寫 `drink-enabled-wiring.test.js`。
   - 讀 `Drink.kt` 與 `handlers.js`，逐一比對：`ENABLED_PATH` 等於 `/api/drink/` 加 `handlers.js` 的路由名稱 `enabled`；`DRINK_DISABLED_MESSAGE` 以 `DRINK_DISABLED_ERROR`（「戒飲記錄已關閉」）開頭；`STATUS_DISABLED` 與 `HTTP_FORBIDDEN` 相同（A70）。
   - 用**真的** `createHandler(deps)` 與 `runScheduled(deps, nowMs)` 搭配記憶體 stub，走完一整輪：打開 → 記一筆 → 關閉 → 寫入被擋、詢問不發、統計仍可讀 → 打開 → 恢復。只准替換外部服務（Gemini、FCM、D1、時間）；`handlers.js`、`drink.js` 不得 monkeypatch。
2. **App ↔ 網頁**：`OverlayService.kt` 呼叫的 `setDrinkEnabled` 與 `index.html` 定義的 `window.pet.setDrinkEnabled` 完全同名；`index.html` 的 `#mic`、`#resist`、`#history` 三個 id 存在；`node backend/tools/check-dom-ids.mjs` 零缺漏（V59 仍通過）。
3. **設定畫面 ↔ 後端不得被改動的設定處理**：`DrinkSettingsActivity.kt` 的儲存流程確實先 `PUT` 設定、成功後才 `PUT` 開關，且送出的設定 body **沒有** `enabled`（A62、M43-S15）。
4. **主畫面沒被動到**：`activity_main.xml` 與 `MainActivity.kt` 對 T0a 記錄的基準 commit 沒有差異（V64）。

發現缺口時：只做對齊修正；缺口屬於不在本批次範圍的檔案時，不得改，寫 BLOCKERS.md「前置批次接線缺口」並停止後續階段（計畫書 §4.7 末段）。
