## 0. 執行協定（最高優先，違反即為失敗）

### 0.1 不提問
全程不得向使用者提問，包含確認、選擇、澄清。

### 0.2 工作循環
    階段實作 → 執行 ./verify.sh → 全綠？
                                  ├─ 是 → 下一階段
                                  └─ 否 → 自動修正 → 重跑

### 0.3 錯誤指紋斷路器【條款 1】
每次修正前，取失敗訊息的前三行做正規化後雜湊，得到一枚「錯誤指紋」，記錄下來。
若同一枚指紋第二次出現，**立刻停止該項目**，寫入 BLOCKERS.md
（含指紋、完整錯誤、已嘗試的修法、你判斷的根因），然後繼續處理其他項目。
輪數上限作為第二道防線，設為 3。
**不得為了讓指紋不同而改寫錯誤訊息或包裝例外。**

### 0.4 分層驗收【條款 2】
verify.sh 分三層，依序執行，前一層失敗就不進入後一層：

- **L1（秒級）**：靜態檢查、匯入檢查、grep 類的結構與架構檢查
- **L2（十秒級）**：單元測試與編譯（`:core:test`、`:app:compileDebugKotlin`、`node --test`），不含覆蓋率統計
- **L3（分鐘級）**：`assembleDebug`、Lint、突變測試、報告、完整回歸

**各階段的驗收只跑 L1 與 L2（`./verify.sh`）。L3（`./verify.sh --full`）只在最後一個階段跑一次。**
不得在 verify.sh 中吞掉任何一層的失敗回傳碼。

### 0.5 成本記錄【條款 6】
每階段結束時在 PROGRESS.md 記錄：該階段的修正輪數、出現過的錯誤指紋清單、每個驗收項各失敗過幾次。

### 0.7 語言與程式風格
所有註解、文件、commit 訊息、使用者看得到的文字使用**繁體中文（臺灣用語）**。
- **JavaScript（`backend/core/`、`backend/worker/`）**：照現有 `backend/core/drink.js`、`backend/worker/handlers.js` 的寫法：ES module、`// 常數定義`、`// 功能函數定義`、箭頭函式、`const`、不加分號、每個函式上方一行中文註解、常數集中在檔案上方。
  範例（照這個樣子）：
  ```js
  // 常數定義

  // 功能函數定義
  ```

## 4. 模組介面規格

不得修改既有函式的簽名，否則既有驗收會連鎖失效。`shouldAsk` 只能加**選用**參數（有預設值），既有呼叫端與凍結測試不必改。

### 4.1 `backend/core/drink.js`（純函式，不讀時間、不讀檔、不連線）

```js
// 常數定義
const ENABLED_FALSE_TEXT = 'false'
const ENABLED_ERROR = '設定值不正確：啟用戒飲記錄'

// 功能函數定義
// 把存起來的文字轉成是否啟用：只有明確存成 'false' 才算關閉，其餘（含 null、undefined、沒存過）一律開啟
export const isDrinkEnabled = (stored) => ...

// 驗證請求內容：必須是物件且 enabled 恰為布林值（true 或 false）；字串、數字、null、缺少欄位一律不合格
// 合格回 { ok: true, enabled }；不合格回 { ok: false, error: '設定值不正確：啟用戒飲記錄' }
export const parseDrinkEnabled = (payload) => ...

// shouldAsk 新增選用的 enabled（預設 true）；enabled 恰為 false 時一律回 false，其餘邏輯不變
export const shouldAsk = ({ hour, askTime, askedOn, todayKey, logs, enabled = true }) => ...
```

### 4.2 `backend/worker/handlers.js`

- 新增常數：`DRINK_ENABLED_KEY = 'drink.enabled'`（沿用 `DRINK_SETTING_PREFIX` 組出，值必須就是這個字串）、`DRINK_DISABLED_ERROR = '戒飲記錄已關閉'`、`DRINK_GUARDED_ROUTES = ['parse', 'preview', 'confirm', 'resist', 'undo']`、`HTTP_FORBIDDEN = 403`。
- 新增處理函式與路由：`enabled: { GET: handleDrinkEnabledRead, PUT: handleDrinkEnabledWrite }`（加進 `DRINK_ROUTES`）。
  - `GET /api/drink/enabled` → 200 `{ "enabled": true|false }`。讀取用 `isDrinkEnabled(await deps.store.readSetting(DRINK_ENABLED_KEY))`。
  - `PUT /api/drink/enabled` → 用 `parseDrinkEnabled(await readPayload(request))` 驗證；不合格回 400 `{ "error": "設定值不正確：啟用戒飲記錄" }` 且**不寫入**；合格就 `writeSetting(DRINK_ENABLED_KEY, 'true' 或 'false')`，回 200 `{ "enabled": … }`。
- `handleDrink`：在找到 route 與 handler 之後、呼叫 handler 之前，若 `name` 在 `DRINK_GUARDED_ROUTES` 內且 `isDrinkEnabled(...)` 為 false，回 403 `{ "error": "戒飲記錄已關閉" }`，**不呼叫** handler（因此不呼叫語言模型、不寫紀錄）。404、405 的判斷順序維持不變（不認得的路徑仍是 404，方法不對仍是 405，且不讀開關）。
- `runScheduled` 的「1. 每日戒飲詢問」：讀 `readSetting(DRINK_ENABLED_KEY)`，把 `enabled: isDrinkEnabled(...)` 傳進 `shouldAsk`。關閉時不讀紀錄以外的任何東西、不呼叫語言模型、不送推播、不寫 `drink.askedOn`。既有的 `try/catch` 維持（排程裡單項失敗不影響後面的盤前均線與 Todoist）；**但不得在 `catch` 內把 `enabled` 當成 true 再繼續詢問**（A63）。
- `readDrinkSettings` 與 `handleDrinkSettingsWrite`、`DRINK_SETTING_FIELDS`、`validateDrinkSettings` 一個字都不改（A62）。

### 4.3 `core/.../drink/Drink.kt`（只追加）

```kotlin

const val STATUS_DISABLED = 403                                     // 狀態：戒飲記錄已關閉
const val DRINK_DISABLED_MESSAGE = "戒飲記錄已關閉，請到「戒飲設定」重新開啟"  // 回 403 時的提示（以 Worker 的「戒飲記錄已關閉」開頭）

// 角色泡泡要不要顯示戒飲按鈕：只有「成功（2xx）且明確讀到 enabled 為 false」才隱藏；
// 非 2xx、沒設定、連不上、讀不到或格式不對（enabled 為 null）一律顯示（M43-S10 唯一允許的降級）
```

| 問題 | 預設值 |

## 8. 絕對禁止事項

- 不得向使用者提問。
- 不得連線真實外部服務、不得呼叫真實 API（驗收全程只用 stub）。唯一例外：突變測試工具無法執行時，可唯讀瀏覽 GitHub 搜尋替代品（見 §7），結果不影響任何驗收判定。
- 不得建立含真實憑證的檔案；不得在 log、錯誤訊息、回應中寫出存取密鑰或伺服器回應內容。
- 不得設遠端、不得 push、不得部署（`wrangler deploy`、`wrangler secret`、`d1 execute --remote` 一律不執行）。
- 不得刪除或覆蓋既有檔案內容；`Drink.kt` 只能追加（外加 `workerErrorMessage` 的一行）；`shouldAsk` 只能加選用參數。
- 不得修改 §1「不動」列的任何檔案；特別是主畫面（`activity_main.xml`、`MainActivity.kt`）、`wrangler.toml`、`wrangler.local.toml`、`schema.sql`、`/api/drink/settings` 的處理函式、所有圖片檔。
- 不得把 `enabled` 加進 `DRINK_SETTING_FIELDS` 或 `validateDrinkSettings` 的回傳。
- 不得新增 `@JavascriptInterface`；不得對 `ChatActivity` 或 `MaActivity` 加 `addJavascriptInterface`。
- 不得在 App 端為開關新增任何本機儲存。
- 不得在 `drinkUiEnabled`、`isDrinkEnabled`、`controlsVisibility` 以外的地方寫「讀不到就預設為開」的備援。
- 不得改寫使用者確認過的任何句子（§4.6 的預期結果、§4.2 與 §4.3 的錯誤與提示文字）。
- T0b 之後不得修改兩個 spec 目錄的任何檔案。
- 不得自製突變量測工具；不得 clone、下載、安裝或執行搜尋到的替代品。
- 不得安裝與本計畫無關的套件。
- 不得執行 `docs/M4.3-CHEAP-PLAN.md` 的內容。
