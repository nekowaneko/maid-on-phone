### 0.3 錯誤指紋斷路器【條款 1】
每次修正前，取失敗訊息的前三行做正規化後雜湊，得到一枚「錯誤指紋」，記錄下來。
若同一枚指紋第二次出現，**立刻停止該項目**，寫入 BLOCKERS.md
（含指紋、完整錯誤、已嘗試的修法、你判斷的根因），然後繼續處理其他項目。
輪數上限作為第二道防線，設為 3。
**不得為了讓指紋不同而改寫錯誤訊息或包裝例外。**

### 0.4 分層驗收【條款 2】
verify.sh 分三層，依序執行，前一層失敗就不進入後一層：

- **L1（秒級）**：靜態檢查、匯入檢查、grep 類的結構與架構檢查
- **L2（十秒級）**：單元測試與編譯（`:core:test`、`:app:compileDebugKotlin`、`node --test`），不含覆蓋率統計
- **L3（分鐘級）**：`assembleDebug`、Lint、突變測試、報告、完整回歸

**各階段的驗收只跑 L1 與 L2（`./verify.sh`）。L3（`./verify.sh --full`）只在最後一個階段跑一次。**
不得在 verify.sh 中吞掉任何一層的失敗回傳碼。

### 0.5 成本記錄【條款 6】

## 4. 模組介面規格

### 4.1 `core/.../ma/MaEntry.kt`（純函式）

```kotlin
// 常數定義
const val MA_ENTRY_LOADING = "正在取得今天的資料…"
const val MA_ENTRY_FAILED = "今天的資料沒拿到，點了可重試"
const val MA_ENTRY_EMPTY = "還沒有追蹤標的，點了去加入"
const val MA_ENTRY_NONE = "還沒有報告，明天 08:30 會送來"
const val MA_ENTRY_NOT_SET = "尚未設定連線"
const val CHAT_ENTRY_SUBTITLE = "女僕：今天也辛苦了，要不要聊聊？"
const val MA_REPORT_PATH = "/api/ma/report"

// App 這次取資料的結果類型：沒設定連線、連不上、有回應（含非 200）
enum class MaFetch { NOT_SET, UNREACHABLE, RESPONDED }

// 從 /api/ma/report 回應取出的欄位；取不到或型別不對的欄位為 null
data class MaReportBrief(val status: String?, val reportDate: String?, val u: Int?, val d: Int?, val m: Int?)

// 從回應原文取出摘要欄位；不是 JSON 物件、欄位缺漏或型別不對時對應欄位為 null，不丟例外
fun parseMaReportBrief(body: String?): MaReportBrief

// 把 "2026-10-12" 轉成 "10/12（一）"（月日不補零，星期用一二三四五六日）；格式不對或日期不存在回傳 null
fun maDateLabel(reportDate: String?): String?

// 卡片載入中的副標
fun maEntryLoadingText(): String

// 依取資料結果算出卡片副標；規則見下
fun maEntrySubtitle(fetch: MaFetch, httpStatus: Int, brief: MaReportBrief?): String
```

`maEntrySubtitle` 規則（依序判斷）：

1. `fetch == NOT_SET` → `MA_ENTRY_NOT_SET`。
2. `fetch == UNREACHABLE` → `MA_ENTRY_FAILED`。
3. `RESPONDED` 但 `httpStatus != 200`，或 `brief == null` → `MA_ENTRY_FAILED`。
4. `brief.status`：
   - `"ok"`：`maDateLabel(reportDate)` 不是 null，且 `u`、`d`、`m` 都不是 null 且 ≥ 0 → `"<日期標籤>・多頭 <u>、空頭 <d>、其他 <m>"`（分隔符號為全形中點「・」，頓號為「、」；0 檔照寫）；否則 → `MA_ENTRY_FAILED`。
   - `"failed"` → `MA_ENTRY_FAILED`。
   - `"empty"` → `MA_ENTRY_EMPTY`。
   - `"none"` → `MA_ENTRY_NONE`。
   - 其他任何值或 null → `MA_ENTRY_FAILED`。

`parseMaReportBrief` 實作限制（core 沒有 JSON 程式庫，也不得加）：用正規表示式取值。`status`、`reportDate` 取**第一個**出現的鍵；`counts` 取第一個 `"counts"\s*:\s*\{...\}` 區塊再取 `u`、`d`、`m`。回應內 `status`、`reportDate`、`counts` 的位置在 `items` 之前，由輔助測試 `ma-entry-contract.test.js` 釘住（§4.6 W-A）。數字必須是不帶小數點與正負號以外字元的整數；`"u":"3"`（字串）算型別不對 → null。

| `counts` 的其他欄位或額外欄位 | 忽略 |
| HTTP 非 200（含 401、404、429、5xx） | 當作取得失敗（`MA_ENTRY_FAILED`） |
| 回應不是 JSON 或空字串 | `brief` 欄位全為 null，副標為 `MA_ENTRY_FAILED` |
| `status` 是 `ok` 但 `items` 為空 | 不管，副標只看 `status`、`reportDate`、`counts` |
| 同時多次 `onResume` | 每次都重取；不做快取；後回來的覆蓋先回來的（`WorkerApi` 是單執行緒依序送出，所以順序固定） |
| 卡片載入中能不能點 | 能點，行為與其他狀態相同 |
| 沒設定連線時 `cardChatEntry` 點擊 | 沿用 `decideChat`：顯示 `CHAT_NOT_SET_MESSAGE`，不開聊天畫面 |
| 副標太長 | 讓它換行，不截斷、不用省略號 |
| `MA_EXIT_URL` 在一般瀏覽器開網頁時 | 導向無效，頁面不變，不處理（正式只在 `MaActivity` 的 WebView 裡使用） |
| XML 裡的色碼 | layout 既有寫法就有十六進位色碼（`#26FF9F0A` 等），新卡片照同樣寫法；不新增 `colors.xml` 項目也可以 |
| 某套件在此環境安裝失敗時 | 改用標準庫替代方案並記錄在 DECISIONS.md，不得降低安全性 |
| 兩種實作都合理時 | 選較保守、較容易測試的那個 |
| §4.5 沒涵蓋的行為 | 選最保守的做法，記錄在 DECISIONS.md，並寫成建議新增的規格範例列 |
| 規格範例與介面規格（§4）衝突 | 不修改任何一方，寫入 BLOCKERS.md 標記「規格爭議」 |
| §2.2 突變測試工具無法執行（Pitest 不能跑） | 不得自製量測工具，不得安裝或執行替代品。唯讀搜尋 GitHub（最多 5 次、記錄最多 3 個候選：開源免費、支援 Kotlin 與 Windows、近 12 個月有更新、能指定範圍），MUTATION-REPORT.md 追加「M4.1：狀態：待補」並填齊欄位（未執行原因、預定範圍、程式版本、原工具補跑方式、替代品候選、搜尋紀錄），CHECKLIST.md 加「突變測試待補」項，PROGRESS.md 記一行 |
| 安全掃描工具無法安裝 | 改用 grep 常見樣式，記錄在 DECISIONS.md，不得跳過 |
