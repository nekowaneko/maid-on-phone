# AccompanyPet M0.5 — 角色自動恢復計畫

> 背景：M0 手機實測（vivo V2503、Android 16）發現，螢幕關閉後 vivo 會先凍結 App，約 3.5 分鐘後把整個程序收掉，
> 即使已加入 Android 省電白名單、開啟 vivo「允許後台高耗電」與「自啟動」也一樣（見 DECISIONS.md 第 26～28 項）。
> App 被收掉後無法自己收到「螢幕解鎖」通知（Android 8 起的限制），因此改用兩個系統會主動叫醒 App 的機制。
> **2026-10-03 更新：B. 定時巡邏已刪除**（vivo 凍結時會移除鬧鐘，無效；見 DECISIONS.md 第 29 項）。以下保留原計畫作為紀錄，只有 A. 快速設定磚仍有效。
> 本計畫延續 docs/EXPENSIVE-PLAN.md 的執行協定（§0）、程式風格（§0.7）與架構約束（§2），以下只列新增部分。

## 1. 範圍

| 動作 | 對象 |
|---|---|
| 新增 | A. 快速設定磚 `PetTileService`：點一下開／關角色 |
| 新增 | B. 定時巡邏 `WatchdogReceiver`：每 5 分鐘由系統鬧鐘叫醒，角色該在卻不在時重新啟動 |
| 新增 | `core` 的「使用者是否想讓角色開著」紀錄與恢復判斷（純邏輯，可 JUnit 測試） |
| 修改 | `MainActivity`（開始／停止時寫入意圖、精確鬧鐘授權按鈕）、`OverlayService`（啟動與停止時排程／取消巡邏）、`AndroidManifest.xml` |
| 不動 | spec 目錄（凍結）、`docs/` 其他文件、`frames/` |

不做：無障礙服務、開機自動啟動、M1 其他項目。

## 2. 設計

### 2.1 使用者意圖
- 按「開始」或磁磚開啟 → 記錄「想開著」；按「停止」、通知欄「停止」或磁磚關閉 → 記錄「不想開著」。
- 紀錄檔：`filesDir/pet-wanted.txt`，內容 `1` 或 `0`；讀取失敗視為 `0`（保守：不自動叫出角色）。
- **只有使用者想開著時才自動恢復**，使用者主動停止後絕不自己跑出來。

### 2.2 恢復判斷（core）

```kotlin
// permission/Restore.kt（套件 com.accompany.pet.core.permission）
enum class RestoreAction { NONE, RESTORE }
fun decideRestore(wanted: Boolean, running: Boolean, hasOverlayPermission: Boolean): RestoreAction
// 只有 wanted && !running && hasOverlayPermission 時回傳 RESTORE

// RunIntentStore.kt（套件 com.accompany.pet.core）
interface RunIntentStore { fun load(): Boolean; fun save(wanted: Boolean) }
class FileRunIntentStore(private val file: java.io.File) : RunIntentStore
const val WATCHDOG_INTERVAL_MINUTES = 5
fun nextWatchdogTime(nowMillis: Long): Long   // now + 5 分鐘
```

### 2.3 A. 快速設定磚
- `PetTileService`：狀態為「開啟／關閉」，跟著服務實際狀態更新。
- 點擊：開著 → 停止並記錄不想開著；關著 → 記錄想開著並啟動服務。
- 沒有懸浮窗權限時改為開啟 MainActivity（顯示權限說明，與 S01 一致）。
- 背景啟動前景服務被系統拒絕時（`ForegroundServiceStartNotAllowedException`），改為開啟 MainActivity 並自動按「開始」。

### 2.4 B. 定時巡邏
- 服務啟動時排程鬧鐘；鬧鐘觸發 `WatchdogReceiver` → `decideRestore` → 需要時啟動服務 → 排下一次。
- 使用者停止時取消鬧鐘。
- 有精確鬧鐘權限（`canScheduleExactAlarms()`）時用 `setExactAndAllowWhileIdle`（Android 12 起屬於可從背景啟動前景服務的例外），沒有時退回 `setAndAllowWhileIdle`（時間可能延後）。
- MainActivity 新增「允許自動恢復」按鈕，帶到系統的精確鬧鐘授權頁。
- 啟動被系統拒絕時只記 log，等下一次巡邏，不嘗試繞過系統限制。

## 3. 架構約束（新增）

| # | 約束 | 檢查 |
|---|---|---|
| A8 | `WatchdogReceiver` 宣告 `android:exported="false"`（只接受自己的鬧鐘） | V18 |
| A9 | `PetTileService` 宣告 `android.permission.BIND_QUICK_SETTINGS_TILE`（只有系統能綁定） | V19 |
| A10 | 自動恢復必須先檢查使用者意圖，`decideRestore` 是唯一判斷入口 | 輔助測試＋人工檢查 |

## 5. 預設值

| 問題 | 預設值 |
|---|---|
| 巡邏間隔 | 5 分鐘（`WATCHDOG_INTERVAL_MINUTES`）；系統可能延後 |
| 意圖紀錄讀取失敗 | 視為不想開著 |
| 磁磚標題 | 陪伴角色 |
| 精確鬧鐘權限 | 不強制；沒有時退回一般鬧鐘 |
