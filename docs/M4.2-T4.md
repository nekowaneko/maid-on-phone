## 為什麼這一階段要寫程式

單元測試全綠只證明零件各自可用，不證明零件被接上。這一階段的任務是找出「接不上」的地方並對齊，同時留下一道永久的自動檢查（條款 11）。它**只做對齊修正，不得新增功能**。

## 必讀

計畫書 §4.6（W-A、W-B、W-C）、§5 的 T4 段落、§6.1 的 V47、V51、V53、V59。

## 步驟

1. 寫 `check-dom-ids.mjs`：讀 `web/app.js`、`call.js`、`background.js` 內所有 `getElementById('…')`、`querySelector('#…')` 的 id，逐一確認存在於 `index.html`；程式動態建立的 id 列在腳本頂端的例外清單，每個註明來源行；有缺漏以非零結束並印出缺的 id。
2. 跑它，列出缺漏。缺的 id 補進 `index.html`，或移除對應的程式段落（`background.js` 不得改，若是它缺 id，補在 `index.html`）。
3. 確認三個事件名稱兩邊完全相同：`app.js` 發出的 `companion:send`、`companion:reply-start`、`companion:reply-failed`，與 `call.js` 監聽的。
4. 確認 `renderer.blink` 真的被 `call.js` 呼叫，且 `zOrder` 只剩 `face` 時 `createRenderer` 能建立。
5. 確認三處 `chat-exit://close` 相同（`call.json`、`Chat.kt`、`call-state.js`，V47），且 `call.js` 導向的是 `CHAT_EXIT_URL`、`ChatActivity` 攔截的是同一個值。
6. 把 `check-dom-ids.mjs` 接進 `verify.sh` 的 L1 成為 V59；**用一份少了某個 id 的 `index.html` 複本實際跑一次，確認它會失敗**（驗收腳本本身也要用觸發輸入驗過）。

## 完成條件
