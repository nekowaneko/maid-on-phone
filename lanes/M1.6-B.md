## 決策

1. **cue 的時間點照規格、不照 accompany_bot**：accompany_bot 的 `applyCuesUpTo(count)` 會在「第 count 個字出現時」演掉 index ≤ count 的 cue，也就是比標籤所在的字早一個字換臉；§4.3 與 M16-S10 規定 index i 的 cue 落在第 i+1 個字的時間。以凍結的規格為準。
2. **開頭連下多個標籤**（如 `[pout][smile]你好`）：index 0 有多個 cue 時，開頭的臉取最後一個（真正生效的表情），不排出中間那張。理由：§4.3 只說「index 0 的 cue」，取生效者最接近聊天網頁 `applyCuesUpTo(0)` 依序蓋掉的結果，且不會閃一張臉。
3. **index > 0 的同位置多個 cue**：依序全部排入（同一時間），與聊天網頁依序套用一致；解析器只記真正的變化，實際上很少發生。
4. **字數以 JS 字串長度（UTF-16 單位）計**：與 stream-parser 的 cue index 同一基準，也與聊天網頁 `text.slice(0, shownCount)` 相同。代價是表情符號（代理對）逐字時會有一格只出現半個字元，照抄 accompany_bot 不另處理。
5. **非字串的台詞**：`planTimeline`／`stageSkip` 解析時當成空字串，不丟例外（保守）。`say` 收到非字串或空字串一律忽略（§7 的空字串規則延伸）。
6. **atMs 為 0 的步驟（開頭的臉）同步套用**，不用 `setTimeout(…, 0)`，避免先閃一格舊臉。結束時的 `stageFinish` 計時器排在結尾換臉之後（同一時間的計時器依註冊順序觸發）。
7. **換臉的實作**：用一張背景 `Image` 先載入，`onload` 才換到畫面上的 `#idle`；以遞增的請求序號只採用最新一次的結果，避免快速連換時舊圖晚到蓋掉新圖。`onerror` 時保留上一張臉；只有要換回平常的臉（`idleFrame`）也載入失敗時，才退回 `frames/placeholder-idle.svg`（§7「仍載入失敗時才退回 placeholder」）。
8. **眨眼**：以「畫面上真正顯示的檔名」判斷是否為 `idleFrame`（不是以請求的表情判斷），換成其他表情時取消眨眼並收起眨眼圖，換回 idle 且正在播放時才恢復排程；`doBlink` 觸發時再檢查一次。
9. **跳到演完後泡泡捲回頂端**（`scrollTop = 0`）：完整台詞從頭讀起；逐字中則每個 count 步驟捲到底（§7）。
10. **`setRender('paused')` 期間收到 `say`**：照常排計時器開演，不自動跳到演完。理由：§4.3 只規定「暫停時若正在演出則跳到演完」；暫停期間 WebView 計時器可能被節流，畫面恢復後接著演，不會遺失台詞。若實機觀感不佳，建議整合時考慮在 Kotlin 端暫停時不呼叫 `showScript`（不在本線實作）。
11. **`showText` 一律把臉設為平常的臉**（§4.3「臉為平常的臉」）；沒在演出時臉本來就是平常的臉，`setFace` 對同一張圖不重載。
12. **同步腳本**的進入點以「直接執行」判斷（比較 `import.meta.url` 與 `process.argv[1]`，Windows 不分大小寫），讓輔助測試可以 import `buildVendor` 而不寫檔；`--check` 不一致或檔案不存在時印出 vendor 檔與來源檔的相對路徑，以 1 結束。

## 阻擋

### V28：`verify.sh` 第 118 行的替換字串是控制字元 0x01，不是 `\1`（斷路器停止，指紋 `5e3838ab558d`）

- 完整錯誤：`❌ V28 找不到 script：`（後面接一個不可見的 0x01 字元），`./verify.sh --lane B` 以 1 結束。
- 根因：`verify.sh` 第 118 行為
  `SRCS=$(grep -oE '<script[^>]*src="[^"]*"' "$PET_ASSETS/index.html" | sed -E 's/.*src="([^"]*)"/<0x01>/' || true)`
  sed 的替換部分是位元組 0x01（`cat -A` 顯示為 `^A`），應為反向參照 `\1`（推測是產生腳本時 `\1` 被當成八進位跳脫）。結果每個 `<script src="…">` 都被換成 0x01，`[ -f "$PET_ASSETS/<0x01>" ]` 永遠失敗。只要 `index.html` 依 §4.3 載入任何外部 script，V28 必定失敗；B1 時 `index.html` 還沒有 `<script src>`，所以沒有觸發。
- 已嘗試的修法：無（缺陷在 `verify.sh`，屬契約檔，本線不得修改；也不以改寫 `src` 引號等方式繞過檢查）。
- 佐證：把 `verify.sh` 複製到 scratchpad、只把這一個 0x01 換成 `\1`，從 worktree 根目錄以 `bash -s -- --lane B < 副本` 執行，結果 `🎉 L1＋L2（B 線）全部通過`（V01～V28 的 L1 全過、V27 通過；V28 確實檢查了 `emotion-map.js`、`vendor/stream-parser.js`、`performance.js` 三個存在的本機相對路徑）。副本未放入 worktree。
- 影響：B2 程式已完成並 commit，但正式 `./verify.sh --lane B` 停在 V28。整合時的 `--full` 也會在 V28 失敗，C、D 線不受影響（三條線都跑 L1，但只有 B 線會改 `index.html`；合併 B 後 V28 才會出現）。

規格爭議：0 項。
